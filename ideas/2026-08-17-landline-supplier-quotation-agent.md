# 座机自动询价助手

- 提出日期：2026-08-17
- 检索日期：2026-08-17
- 状态：已完成

## 原始灵感

> 我想做一个可以连接座机自动通过座机给原材料厂商询价

## 灵感解读

- 目标用户：需要反复向固定原材料供应商电话询价的采购员、采购助理和中小制造企业；当前按企业内部自用分析，不假设立即产品化。
- 使用场景：从询价单读取规格、牌号、数量和交付地，经已有企业电话号码联系已建立业务关系或已授权的供应商，收集口头报价及完整交易条件。
- 核心问题：人工拨号、等待转接、重复念规格、追问税运与交期、再把口头信息录入表格，耗时且容易在数字、单位和条件上抄错。
- 期望结果：自动完成低风险的询问和记录，输出逐字段可回听、可复核的结构化报价；任何采购承诺、供应商选择或订单提交都留给人。
- 主要工作流程：导入询价单 → 校验供应商授权与呼叫规则 → 拨号及处理 IVR/等待 → 披露 AI 身份和录音安排 → 逐项询价与读回确认 → 结构化提取 → 证据绑定和异常标记 → 人工复核 → 导出报价对比表。
- 可能形态：优先是“采购询价工作台 + 企业电话/SIP 接入 + 语音代理 + 报价审计层”，不是一个脱离现有号码和采购数据的通用外呼机器人。

### 已知信息与关键未知项

用户当前不清楚电话环境，因此不能直接确定硬件。落地前应由电信/IT 人员用约 30 分钟确认：墙上电话线是运营商模拟线还是 PBX 分机、PBX 品牌型号、是否有 SIP 中继或 SIP 分机、外呼显示号码、并发线路数、是否已录音、运营商是否允许程序化外呼。报告同时覆盖以下三条路径：

| 当前电话环境 | 正确接入方式 | 不应直接假设 |
|---|---|---|
| 传统模拟座机/PSTN | 运营商模拟线接 **FXO** 网关，转换为 SIP 后进入 Asterisk/语音代理 | 普通 FXS ATA 主要用于接模拟话机，不等于能接运营商外线 |
| 企业 PBX | 优先开 SIP 中继或 SIP 分机；老式数字/专有分机需对应厂商网关 | 不能把数字分机口当普通模拟线接入 |
| 已有 SIP/VoIP | 直接配置经运营商批准的 SIP 中继和真实主叫号码 | 不能用改号、灰色线路或未经许可的互联网电话绕接公网 |

## 结论摘要

- **技术上可行，但不是“插根电话线就能用”。** 最小系统至少包含电话接入、实时语音编排、中文术语识别、询价状态机、报价证据与人工复核六层。电话环境不清楚时，先盘点而不是先买网关。
- **未发现端到端现成产品。** 本次保留 18 个可信候选。LiveKit、Vapi、Retell、阿里云智能外呼等能拨号、转接和生成通话记录；SAP Ariba、Coupa 能管理正式 RFQ；但没有候选原生完成“座机联系长尾原料供应商并把口头数字变成逐字段可回听的报价单”。
- **首选架构是国内合规线路 + SIP + 可替换语音编排。** 若 PBX 已支持 SIP，优先 `企业 SIP/PBX → LiveKit Agents 或 Pipecat → 国内中文 ASR/TTS → 询价与审计服务`；若只有模拟线，再加 FXO 网关与 Asterisk。
- **最快验证可考虑阿里云智能外呼，但应先确认场景准入和线路成本。** 官方资料显示其支持企业外呼和自有呼叫中心 SIP 对接；截至检索日，按量平台费为 0.08 元/呼叫尝试，通信线路另计，自带非推荐线路的 SIP 接入页面列出 30,000 元一次性费用，可能不适合小规模试验。[阿里云产品说明](https://help.aliyun.com/zh/outboundbot/)；[计费说明](https://help.aliyun.com/en/outboundbot/product-overview/billing)
- **海外一体化平台不宜直接作为中国生产首选。** Vapi、Retell 和 Bland 功能成熟，但应先核验中国号码可达性、国内运营商准入、时延、录音/联系人跨境传输和供应商条款；能拨通不等于可长期合规稳定使用。
- **报价准确性必须靠流程约束，而不是只靠更强模型。** 价格、币种、含税状态、单位、运费、最小起订量、交期、付款条件和有效期必须逐项读回确认，并绑定录音时间戳；低置信度或前后冲突时不能生成“已确认报价”。
- **差异化方向是“可审计口头报价捕获层”。** 通用语音平台已有结构化输出，采购平台也有 RFQ 数据模型；真正缺口是把每个关键字段绑定到原始音频、识别文本、供应商口头确认和人工复核状态，服务不愿登录门户或习惯电话报价的长尾供应商。
- **合规上应按“应邀、可识别、可退出、可追溯”设计。** 采购询价未必等同于向消费者营销，但不能因此放宽边界：优先联系已授权供应商，开场说明公司及 AI 身份，说明录音用途并允许拒绝/转人工，按供应商营业时间限频，维护禁呼名单，使用真实可追溯主叫。
- **只把系统定位为询价记录助手。** 它不得接受价格之外的合同承诺、变更付款账户、确认采购量、授标或下单；所有报价必须经人工复核后才可进入采购决策。

## 理想流程与报价数据模型

### 端到端流程

1. 采购员导入 Excel/ERP 询价单，系统冻结版本并检查材料编码、规格、数量、单位、交付地和期望回复日期。
2. 系统只选择状态为“已授权自动联系”的供应商联系人，检查营业时间、最近呼叫次数、禁呼状态和真实主叫线路。
3. 接通后先说明：“您好，我是 **某公司采购部门的 AI 询价助手**，受采购员委托询问以下材料。本次通话是否可以继续？为准确记录报价，是否同意录音？您可随时说‘转人工’。”若对方不同意，则转人工或结束。
4. 处理总机、IVR、分机、等待和转接；可发送 DTMF，但不得尝试猜测密码或绕过访问控制。LiveKit 官方已提供 DTMF、IVR 识别、应答机检测及人工协助转接能力；Vocode 文档也展示了 IVR 等待、DTMF 和转人工。[LiveKit DTMF](https://docs.livekit.io/telephony/features/dtmf/)；[Vocode IVR](https://github.com/vocodedev/vocode-core/blob/main/docs/ivr-navigation.mdx)
5. 每种材料先完整念规格，再询问可供数量、报价单位、单价/总价、币种、税率/含税状态、运费承担、交货期、付款条件、起订量和报价有效期。
6. 每个关键数字立即读回确认，例如：“我确认一下：Q235B，三毫米，含 13% 税到厂价每吨 3,860 元，交期 7 天，对吗？”供应商只确认当前字段，不能用整段模糊的“对”替代多个冲突字段。
7. 通话后运行两次提取：实时结果用于追问，离线结果用于复核；保存原始口述值和标准化值，单位换算不得覆盖原文。
8. 输出报价对比表。缺失、矛盾、低置信度、仅由模型推断或未被供应商读回确认的字段醒目标红。
9. 采购员逐条回听关键音频后签署“人工已复核”；在此之前只能是“询价记录草稿”，不得进入自动授标或下单流程。

### 最小报价记录

| 字段 | 必须保存的证据 | 自动化规则 |
|---|---|---|
| 供应商与联系人 | 联系人来源、授权状态、主被叫号码、通话时间 | 联系人来源不明或已拒绝时禁止呼叫 |
| 材料 | RFQ 行号、原始名称/牌号/规格、供应商复述 | 规格未复述或映射不唯一时转人工 |
| 数量与单位 | 口述原文、标准单位、换算公式、音频时间戳 | 模型不得自行补单位 |
| 单价/总价与币种 | 数字原文、标准化数字、读回确认片段 | 任一数字冲突则标记“未确认” |
| 税与运费 | 含税/未税、税率、到厂/自提、运费承担 | 缺失时不可直接比较“最低价” |
| 交期与可供量 | 起算点、自然日/工作日、分批条件 | “尽快”“差不多”保留为模糊文本并追问 |
| 付款、起订量、有效期 | 供应商原话及确认片段 | 不得把历史条件自动套到本次报价 |
| 复核状态 | 模型置信度、冲突、复核人和时间 | 仅“人工已复核”可用于采购决策 |

## 重点方案对比

没有一个候选原生完成完整采购询价，因此下表比较最接近的五种落地选择。

| 方案 | 已覆盖需求 | 主要缺口 | 电话环境与门槛 | 成本、隐私与稳定性 | 结论 |
|---|---|---|---|---|---|
| LiveKit Agents + 国内 SIP + 国内 ASR/TTS | 外呼、IVR/DTMF、应答检测、人工转接、可编程代理 | 询价状态机、报价证据、权限和采购集成都要自建 | SIP 环境门槛中；模拟线需 FXO/Asterisk | 开源利于审计和替换；需自运维；可把核心数据留在境内 | **综合首选**，适合认真做内部系统 |
| Asterisk + FXO 网关 + LiveKit/Pipecat | 兼容模拟座机/老 PBX，电话控制和日志完整 | 硬件、回声/编解码、NAT/SIP、安全和媒体桥接运维较重 | 电话环境门槛最高，但适配面最广 | 有硬件与现场配置成本；本地部署隐私最好；故障点更多 | **模拟线保底方案**，确认没有 SIP 后再用 |
| 阿里云智能外呼机器人 + 合规线路 | 国内企业产品、外呼任务、ASR/TTS/NLU、结果统计、SIP 对接 | 采购数字校验、证据粒度和灵活 Agent 能力需验证/二开 | 企业认证和运营商线路是前置 | 国内数据路径较易治理；平台及线路费用清晰，但自有非推荐线路 SIP 接入费可能高 | **最快国内验证候选**，先问准入与费用 |
| Vapi + 自有 SIP/号码 | 外呼、DTMF/转接、录音、日志、结构化输出和组件替换 | 中国生产线路、跨境数据、中文术语和长期可达性未证实 | 原型门槛低；生产合规门槛高 | 托管编排始终在 Vapi 基础设施，官方说明系统日志仍由其保留；需做跨境评估 | **适合隔离测试，不宜默认生产** |
| Retell AI + 自有 SIP/号码 | 外呼、自有 SIP、转接、逐词工具日志、多声道录音 | 同样缺中国线路和跨境验证；复杂 SIP 场景仍要自写逻辑 | 原型低至中 | 审计工件丰富，但默认示例录音位置为境外对象存储；需逐项核隐私条款 | **审计型海外原型备选** |

### 推荐架构分支

**分支 A：已有 SIP/VoIP（优先）**

`询价单/ERP → 授权与限频服务 → 国内 SIP 中继 → LiveKit Agents/Pipecat → 国内实时 ASR + LLM + TTS → 报价证据库 → 人工复核工作台`

无电话网关；先用一条并发线路。所有关键字段同时保存 RFQ 原值、供应商口述、音频片段、标准化值和复核状态。

**分支 B：企业 PBX**

PBX 支持 SIP 时给系统一个受限 SIP 分机或中继，只允许白名单目的号码并限制并发；PBX 不支持时，优先找原厂 SIP/PRI/E1 方案，不要先从桌面话机耳机口“录音模拟”。

**分支 C：传统模拟座机/PSTN**

`运营商模拟线 → FXO 网关 → Asterisk → SIP/实时媒体 → 语音代理`。FXO 网关须支持本地制式、来电显示、断线检测、回声消除、DTMF、CDR 和可靠的忙音/极性反转判定。先只接一条非关键线路并保留人工话机回退。

## 差异化方向：可审计口头报价捕获层

### 证据与推断

1. Vapi 已能在通话结束后从完整上下文生成符合 JSON Schema 的结构化输出，Retell 也能提供录音、逐词工具调用和多声道工件，证明“电话 → 结构化数据 → 审计材料”的基础能力已商品化。[Vapi Structured Outputs](https://docs.vapi.ai/assistants/structured-outputs-quickstart/)；[Retell Call API](https://docs.retellai.com/api-references/create-phone-call)
2. SAP Ariba 和 Coupa 的正式 RFQ 流程要求行项目、条件和供应商响应具有结构；采购社区反馈则反复提到供应商仍会用 PDF、邮件和 Excel，团队手工抄录与单位统一。这说明真正价值不只是“会打电话”，而是把非结构化口头报价可靠落入既有 RFQ 字段。[Coupa RFQ 类型](https://docs.coupa.com/en/supplier-documentation/coupa-for-suppliers/the-coupa-supplier-portal-or-csp/features-and-processes-in-the-coupa-supplier-portal/sourcing/sourcing-events-types-for-suppliers)；[采购从业者讨论](https://www.reddit.com/r/procurement/comments/1mi7m8k/how_do_you_compare_supplier_quotes_still_manual/)
3. 电话语音链路并不完美。LiveKit issue 中存在电话场景时延增加、打断时音频片段丢失导致转写错误的报告；这是社区个案而非整体质量统计，但足以说明关键数字不能只依赖单次转写。[电话时延 issue](https://github.com/livekit/agents/issues/3685)；[打断转写 issue](https://github.com/livekit/agents/issues/2216)
4. 国内 ASR 官方资料表明热词可提升产品名、公司名和行业术语识别，且腾讯云支持每次请求传临时热词。这支持“从当前 RFQ 动态生成术语表”，但没有证明电话线上所有原料牌号都能达到采购所需精度，必须用本企业录音集实测。[腾讯云热词](https://cloud.tencent.cn/document/product/1093/40996)；[阿里云 ASR 精度增强](https://help.aliyun.com/zh/model-studio/improve-asr-accuracy)

### 产品定义

差异化不是做另一个通用外呼平台，而是在任何电话/语音底座之上增加一个采购专用层：

- 每通电话由冻结的 RFQ 版本驱动，代理只能讨论白名单行项目和允许字段；
- 从 RFQ 自动构建动态热词：供应商简称、材料牌号、规格、单位、交付地；
- 对数字采用“识别 → 标准化 → 读回 → 对方确认 → 音频证据绑定”的五步协议；
- 同时保留 `raw_value` 与 `normalized_value`，单位换算和税运调整都有公式与操作者；
- 每个字段显示证据时间戳、识别置信度、供应商是否明确确认、人工是否复核；
- 只输出候选比较，不自动决定中标；任何账户变更、合同承诺或订单动作立即转人工。

这一路线的证据支持“问题存在且组件可用”，但尚未证明供应商愿意与 AI 报价，也未证明节省的时间足以覆盖线路与维护成本；这两点必须通过授权小样本试验验证。

## 便利性、成本与维护

### 能减少的步骤

- 批量读取 RFQ，减少手工拨号、重复念标准问题和逐字段抄写；
- 自动记录未接、占线、转接、拒绝、需回拨和缺失条件；
- 把税、运、单位、交期和有效期统一呈现，采购员只处理异常和最终复核；
- 通话与报价字段直接互链，争议时无需从整段录音中盲找。

### 成本模型（检索日口径）

| 场景 | 硬件/平台 | 通话及持续成本 | 判断 |
|---|---|---|---|
| 已有 SIP/PBX | 通常不需 FXO；可用现有服务器或小型独立主机 | 国内运营商 SIP/固话资费、ASR/TTS/LLM、运维 | 最低成本起点；先确认 PBX 授权与线路条款 |
| 模拟座机 | 1 台 4 路 FXO 网关 + 本地服务器/虚机 + 备用人工话机 | 原固话资费、硬件维护、Asterisk/媒体链路运维 | 官方厂商多采用询价制；非官方市场价差异大，本报告不把零售报价当事实 |
| 阿里云按量 | 无额外网关（若使用合作线路）；0.08 元/呼叫尝试，月呼叫不超过 100 次官方页面称不收该平台费 | 号码、线路、通信费另计；自有非推荐线路 SIP 接入官方列 30,000 元/次 | 小试验要先问能否使用推荐线路，否则一次性费会主导成本 |
| 自建开源 | 软件许可成本低；服务器视并发而定 | 模型调用、SIP、监控、备份和工程人力 | 隐私与可控性好，真正成本在集成和持续维护 |
| 海外语音 SaaS | 通常无本地硬件 | 平台分钟费 + 电话费 + 模型费；另有跨境评估和网络时延成本 | 未逐项核验 2026-08-17 中国生产可用性，不做当前价格承诺 |

本地服务器、FXO 网关及集成工时只能在电话盘点后估算。第一版不应追求并发：单线路串行拨号既便于审计，也降低投诉、线路风控和故障定位难度。

### 普通话、行业术语与数字准确性

- 采购电话通常是 8kHz 窄带、可能带回声和口音；必须用真实线路录音测试，而不能拿会议麦克风结果代替。
- 每通电话按 RFQ 生成临时热词，并加入数字的多种念法，例如“Q 二三五 B”“Q235B”“三点零毫米”“3 毫米”。
- 关键字段采用确定性校验：数量与单位组合、税率枚举、币种、合理价格区间、交期日期解析；校验失败时追问而非猜测。
- 离线复核可使用第二个 ASR 或另一配置交叉转写；两个结果不一致时必须回听。
- 禁止代理在通话中暗自修正供应商口误；应读回原值并询问确认。

### 维护、隐私和稳定性

- 电话层故障包括线路占用、忙音/挂机检测错误、SIP NAT、防火墙、编码、DTMF、回声和运营商拦截；需保存 CDR、SIP 状态码和媒体质量指标。
- 语音层需监控首字延迟、轮次延迟、打断、漏字、转人工成功率和模型超时；模型不可用时应播放固定提示并结束或转人工。
- 采购数据、联系人、录音、价格和付款条件可能具有商业敏感性；建议境内存储、字段级权限、加密、下载审计、可配置保留期和到期删除。
- 云平台需要逐项确认：音频经过哪些供应商、存储在哪个地区、是否用于训练、保存多久、能否关闭录音、能否自带存储、故障时如何导出。

## 合规与信任边界（中国大陆，检索于 2026-08-17）

以下是产品设计研究，不是针对具体企业和地区的法律意见。上线前应让本企业法务、运营商和线路服务商按实际业务复核。

### 1. 呼叫目的与授权

工信部 2018 年骚扰电话整治文件要求商业营销事先取得用户同意、保留凭证并建立禁呼名单；2020 年呼叫中心管理通知要求严格控制呼出、真实主叫可溯源，并将呼叫中心呼出限定在用户同意的即时回访或信息咨询等合规场景。[2018 工作方案](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2020/art_b22d64db866c4636aea4835414d198e3.html)；[呼叫中心管理通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2020/art_5252be6730fa47ebbfd726c58648e733.html)

采购方向供应商询价与“向用户推销商品”并不完全相同，但自动呼叫仍可能扰民，也受运营商线路用途和风控约束。安全基线应是：

- 由采购员确认双方已有业务关系，或先由人工/邮件/合同取得“可由 AI 电话询价”的授权；
- 首次 AI 电话只做身份说明和授权确认，不直接展开长询价；
- 对方拒绝、要求仅人工联系或号码错误时立即结束并永久进入相应禁呼/人工联系状态；
- 禁止号码段顺呼、陌生联系人购买名单和高频重拨；默认只在供应商公布的营业时间拨打；
- 全国性文件未为本采购场景给出统一精确拨打时段，本报告不臆造小时数，企业应与运营商约定并采用更保守规则。

### 2. 真实主叫与电话资源

《反电信网络诈骗法》禁止非法制造、买卖、提供或使用具有改变主叫号码、虚拟拨号、互联网电话违规接入公用电信网络等功能的设备/软件；工信部通知要求真实主叫鉴权和可溯源。[反电信网络诈骗法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_d30139b442a141f48f05775d8c0b3cee.html)

因此只能使用企业合法取得、经运营商和 SIP/PBX 服务商批准的线路与号码。不得使用 SIM box/猫池、改号、号码伪装、个人手机号私接 SIP 或所谓“防封线路”；阿里云资料也明确自有 SIP 中继不能使用个人移动号码。[阿里云新用户须知](https://help.aliyun.com/en/outboundbot/product-overview/new-user-notice)

### 3. AI 身份披露

《互联网信息服务深度合成管理规定》把合成人声纳入可能需显著标识的深度合成服务；《人工智能生成合成内容标识办法》自 2025-09-01 起施行，并要求适用范围内的音频在起始、末尾或适当位置以语音提示等方式显式标识。[深度合成规定](https://www.cac.gov.cn/2022-12/11/c_1672221949354811.htm)；[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

适用性要区分：面向境内公众提供生成式 AI 服务通常受《生成式人工智能服务管理暂行办法》约束，而企业内部研发应用且未向境内公众提供服务的情形被该办法明确排除；私有采购助手是否落入其他深度合成/网络信息服务规则，仍取决于具体提供方式。[生成式 AI 暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

无论最终法律定性如何，本系统都应在第一句话明确说是 AI 助手，不模仿具体真人声音，不诱导对方误以为正在与采购员本人通话。身份披露同时是降低诈骗疑虑和保证报价授权边界的产品要求。

### 4. 录音、联系人与个人信息

供应商公司名称和公开总机不一定都是自然人个人信息，但联系人姓名、直线电话、声音、录音、通话行为和备注一旦关联可识别自然人，就可能受《个人信息保护法》约束。该法要求合法处理依据、明确合理目的、最小必要、公开透明、事前告知和安全保障；向其他处理者提供或向境外提供还可能涉及单独同意及跨境条件。[个人信息保护法](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)

本次未找到一条可简单概括为“中国所有商业电话录音一律必须双方同意”的全国统一规则，因此不能作此绝对陈述；但民法典保护私人生活安宁和私密活动，个人信息法要求告知与合法处理依据，呼叫中心规定在特定合规呼出中又要求至少留存 30 日录音及主被叫/时间/同意凭证。稳妥设计是开场明确告知录音目的、范围、保存期限和退出方式；不同意录音则转人工或仅记录不含个人声音的最小业务结果，具体方案由法务确认。[民法典](https://gdca.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_573d6ef5018b46b6a4e1f31ca085a710.html)；[呼叫中心管理通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2020/art_5252be6730fa47ebbfd726c58648e733.html)

使用境外 ASR、LLM、TTS 或语音 SaaS 时，音频、电话号码、联系人和报价可能被发送境外。《个人信息保护法》第三十八、三十九条规定了跨境提供的条件、告知和单独同意等要求；应优先选境内处理，或在启用境外方案前做个人信息保护影响评估和合规路径确认。[跨境条款](https://www.npc.gov.cn/WZWSREL25wYy8vLy8vL2MyL2MzMDgzNC8yMDIxMDgvdDIwMjEwODIwXzMxMzA4OC5odG1s)

### 5. 必须内置的安全机制

| 阶段 | 强制门控 |
|---|---|
| 呼叫前 | 授权状态、号码来源、营业时间、最近频次、禁呼名单、RFQ 冻结版本、真实主叫、目的号码白名单 |
| 开场 | 公司名称、AI 身份、询价目的、录音安排、继续/拒绝/转人工选择 |
| 通话中 | DTMF 仅走公开 IVR；允许口头/按键转人工；遇账户变更、合同承诺、强烈异议、无法确认数字立即停止自动处理 |
| 报价记录 | 关键字段逐项读回；音频时间戳；原始值与标准化值并存；缺失/冲突/低置信度不补写 |
| 通话后 | 禁呼和纠错立即生效；访问日志；录音及文本按策略保留/删除；人工签署后才能用于比较 |
| 采购决策 | AI 不授标、不下单、不承诺价格/数量/付款，不自动修改供应商银行账户或主数据 |

## 下一步验证

### 阶段 0：不拨外部电话的环境与数据盘点（1 天）

1. 拍照记录座机、墙线、PBX/网关设备铭牌和运营商账单中的线路类型；向 IT/运营商询问是否支持 SIP、允许的用途、真实主叫和录音要求。
2. 选 20 份历史 RFQ 与对应报价，建立字段字典、材料别名、牌号/规格热词和异常类型，不上传真实联系人到未审批云服务。
3. 明确供应商授权状态：已授权 AI、仅人工联系、未知、拒绝；未知一律不自动拨号。

### 阶段 1：离线录音与内部模拟（3–5 天）

不联系供应商。由内部同事扮演总机和供应商，覆盖普通话、山东口音、噪声、等待、打断、改口、多个单位及含税/未税价格。用真实电话链路或 8k 模拟音频比较两个 ASR 方案。

**通过门槛**：

- 价格、数量、单位、税率、交期等关键字段在读回后的精确匹配率 ≥ 98%；未达到时系统必须标红而非悄悄填值；
- 100% 关键字段能在两步内回到对应音频片段；
- 转人工/结束指令成功率 100%；
- 无权限时无法呼叫非白名单号码，日志能解释每次尝试；
- 典型对话中断和超时不会产生采购承诺。

### 阶段 2：经明确授权的 3–5 家供应商小试（需法务、运营商和供应商同意）

只询问 1–3 种低风险、规格明确的常购材料；单线路、工作时间、每家最多一次，不自动重拨。采购员实时旁听并可随时接管，通话后逐项向供应商/采购员核验。

**成功信号**：平均每份报价的人工处理时间下降至少 30%；关键字段复核后无实质错误；所有供应商理解 AI 身份和退出方式；无重复联系、投诉或线路告警；采购员认为证据链比原人工笔记更易审计。

**暂停条件**：供应商明显不愿与 AI 对话；关键字段精确匹配低于门槛；电话延迟持续影响自然追问；运营商不批准用途；出现一次未授权外呼、禁呼失效、错误采购承诺或无法追溯的报价字段。

## 推荐顺序

1. **先盘点电话与授权，不采购硬件。** 如果已有 SIP，直接排除 FXO 网关支出。
2. **先做离线“报价证据层”。** 用历史/内部模拟录音证明数字读回、结构化和回听工作台有价值，这部分不依赖最终电话平台。
3. **国内线路优先。** 与现有运营商、PBX 服务商及阿里云等国内平台确认询价场景准入、号码、SIP、录音和资费；拿到书面答复后再比较自建与托管。
4. **首版单线路、人工旁听。** 不做批量并发、不做自动重拨、不做自动下单。
5. **若验证通过，再决定底座。** 长期可控和集成能力优先选 LiveKit/Pipecat + 国内 SIP；只有模拟线时加 Asterisk + FXO；阿里云适合验证其费用和流程可接受的企业。
