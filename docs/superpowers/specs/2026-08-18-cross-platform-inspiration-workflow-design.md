# 跨工具轻量 AI 灵感工作流设计

## 状态

已确认，等待实施计划。

## 1. 目标

将 Inspiration 优化为面向 Codex、Claude Code 和 Cursor 用户的跨工具 AI 灵感研究工作台。它不再要求生成完整研究报告，而是把自然语言灵感快速沉淀为一张可追踪的轻量 Markdown 卡片。

每张卡片回答四个问题：

1. 这个灵感是什么；
2. 它与已有灵感有什么关系；
3. 外部已有方案中哪些可以复用；
4. 下一步最小行动是什么。

## 2. 范围

### 包含

- 面向 Codex、Claude Code 和 Cursor 的入口适配器；
- 一份平台无关的核心工作规则；
- 中文和英文 README、核心规则对照和卡片模板；
- 研究前检查 `ideas/INDEX.md` 及关联卡片；
- 在卡片中记录已有灵感关系与可直接复用内容；
- 按需检索少量最相关的 GitHub 项目、产品或资料；
- 继续使用 Markdown 文件和 Git 进行长期保存。

### 不包含

- 完整研究报告、固定候选数量或固定深度对比；
- 向量数据库、嵌入模型、独立后端或 Web 界面；
- 自动刷新所有旧卡片；
- 为同一灵感生成中英文两份内容重复的卡片；
- 宣称 Claude Code 或 Cursor 具备 Codex 的独立任务创建能力。

## 3. 目标用户与定位

目标用户是希望在多个 AI 编程工具中持续记录和筛选 AI 使用想法的个人用户。公开定位为：

> A lightweight, cross-tool prior-art workspace for AI workflow ideas. Capture an idea, check related work, record what can be reused, and choose the next small step.

中文定位为：

> 一个跨 Codex、Claude Code 和 Cursor 的轻量 AI 工作流灵感工作台：记录灵感、检查相近方案、标记可复用内容，并确定下一步行动。

## 4. 架构与文件结构

```text
Inspiration/
├─ README.md                         # 英文完整说明
├─ README.zh-CN.md                   # 中文完整说明
├─ AGENTS.md                         # Codex 适配器
├─ CLAUDE.md                         # Claude Code 适配器
├─ .cursor/rules/
│  └─ inspiration-workflow.mdc       # Cursor 适配器
├─ instructions/
│  ├─ core-workflow.md               # 唯一规范性核心规则
│  └─ core-workflow.zh-CN.md         # 中文完整对照
├─ templates/
│  ├─ inspiration-card.en.md         # 英文轻量卡片模板
│  └─ inspiration-card.zh-CN.md      # 中文轻量卡片模板
├─ ideas/
│  ├─ INDEX.md                       # 唯一索引
│  └─ YYYY-MM-DD-<slug>.md
└─ scripts/
   └─ validate-workspace.ps1
```

`instructions/core-workflow.md` 是唯一具有规范效力的核心规则。中文文件是完整对照，存在歧义时以英文规范文件为准。三个适配器只负责加载核心规则和描述平台差异，不复制完整研究流程。

## 5. 灵感处理流程

1. 判断输入是新灵感、既有灵感补充、变体还是普通讨论。
2. 对新灵感先读取索引和相关卡片，判断关系为重复、变体、互补、依赖或无明显关联。
3. 只在缺失信息会改变检索方向时，一次询问一个澄清问题。
4. 按需搜索 1–3 个最相关的 GitHub 项目、产品或资料；找不到时直接记录。
5. 记录可以直接使用或组合的 Skill、Agent、MCP、Prompt、脚本、数据源或设计思路。
6. 给出一个最小可执行的下一步，不要求先开发完整产品。
7. 创建或更新一张轻量卡片，并在 `ideas/INDEX.md` 中登记。

检索重点仍以目标用户、问题、使用场景、工作流和最终产出为主；相同技术栈或关键词本身不构成高度相似。

## 6. 轻量卡片结构

每条新灵感只生成一张卡片，字段如下：

```markdown
# 灵感名称 / Idea title

- 日期 / Date：YYYY-MM-DD
- 状态 / Status：待处理 / queued
- 一句话想法 / One-line idea：

## 已有灵感关系 / Related ideas

- 关系 / Relation：重复、变体、互补、依赖或无明显关联
- 关联卡片 / Related cards：

## 外部参考 / Similar references

- 项目、产品或资料：
- 为什么相关：

## 可复用内容 / What to reuse

- 可以直接使用：
- 需要改造或自行实现：
- 复用风险：

## 下一步 / Next step

- 最小行动：
- 成功信号：
```

字段可按实际情况简化，但不得删除“已有灵感关系”“可复用内容”和“下一步”。

## 7. 跨工具行为

- Codex：具备独立任务能力时，为明显的新灵感创建独立任务，并传递原始表述、日期和卡片要求。
- Claude Code：使用当前环境可用的子任务或新会话能力；不具备时在当前会话完成卡片归档。
- Cursor：默认在当前聊天完成研究，通过独立卡片文件隔离上下文；不宣称自动创建聊天。
- 所有平台：能力不足不能导致灵感丢失。适配器必须说明降级方式。

## 8. 双语策略

- README 和核心规则提供中英文完整版本；
- 卡片按用户当前语言选择模板；
- 一张卡片只使用一种主要语言；
- 项目名、产品名、代码标识和技术术语可保留原文；
- 索引保持单一数据源，标题和字段说明采用中英双语，避免中英文索引分叉。

## 9. 兼容与迁移

现有 `ideas/` 下的三份完整研究报告保持不变。它们继续作为历史资料被索引；优化后新灵感使用轻量卡片，不强制转换旧文件，也不删除现有报告模板，除非后续确认不再需要历史格式。

## 10. 验证标准

静态校验应确认：

- 三个平台适配器、核心规则、双语 README 和双语卡片模板均存在；
- 新规则不再强制 10–20 个候选、3–5 个重点项目或完整研究报告；
- 卡片模板包含已有灵感关系、可复用内容和下一步；
- 索引链接有效且没有重复记录；
- 旧报告没有被修改；
- 中英文核心规则的章节和关键约束一致；
- 文件中没有未完成占位符或待补内容。

端到端验收至少覆盖：全新灵感、相近灵感、平台能力不足、中文输入和英文输入五种情况。

## 11. 成功标准

用户自然描述一个 AI 灵感后，可以在不填写表单的情况下得到一张短卡片，并从卡片中快速看到：

- 它是否与已有灵感重复或互补；
- 哪些外部方案值得直接复用；
- 下一步应该做什么。

整个流程不依赖数据库、向量检索或固定长度的研究报告。
